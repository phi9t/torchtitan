## Question

Which GLM-5.3-Flash architecture elements help, hurt, or are neutral at speedrun scale (~124M parameters, FineWeb,
a few hundred million tokens), and how do they interact? The metric is validation cross-entropy at a matched token
budget, plus tokens-to-target. Wall-clock numbers are `shared_gpu` evidence only, because these runs share the B200
host with the GLM ladder and other users.

## Substrate

TorchTitan-native small GPT in `torchtitan/experiments/glm53_arch_speedrun/`, following the classic modded-nanogpt
speedrun recipe: 12 layers, d768, 6 heads x 128, RoPE, QK-norm, ReLU^2 MLP, untied head, logit softcap, Muon for
hidden matrices and AdamW for embeddings/scalars, trapezoid LR, FineWeb GPT-2 shards, standard FineWeb validation.
GLM elements reuse the HF-verified code in `torchtitan/experiments/glm53_flash/`.

The upstream modded-nanogpt record (`experiments/modded_nanogpt_b200`, upstream `ecbb586`) is an anchor only. Its
stacked tricks (MUDD dense connections, bigram hash embedding, FP8 head/MLP) would confound single-element arms, and
MUDD is itself a relative of mHC.

## Factors

| Factor | Levels | GLM-5.3-Flash setting |
| --- | --- | --- |
| F1 mHC residual | off, on (4 streams, Sinkhorn comb) | on, 4 streams |
| F2 positions | RoPE, NoPE | NoPE |
| F3 mixer | softmax only, KDA 3:1 hybrid | KDA 3:1 ((i+1)%4==0 softmax) |
| F4 sparse attention | dense, indexer top-k, indexer top-k + IndexPool | indexer + IndexPool 4->1 |
| F5 MTP | off, on (1 layer) | 1 MTP layer |
| F6 MoE (optional) | off, on (matched active params) | 288 experts top-8 + shared |

B0 = all factors at the first level. G = the GLM-like setting in every factor.

## Schedule

The study is small-GPU work and is scheduled to fill capacity left over by the large GLM jobs:

- Each cell uses 1-2 GPUs with a hard 24 GiB per-process cap, so it co-runs next to an 8-GPU GLM job
  (~132 GiB/GPU) and foreign jobs.
- `S03` builds a resumable queue (`experiments/glm53_arch_speedrun/queue/`) and a scheduler that launches cells
  whenever a GPU has enough free memory, records state per cell, and retries only on infrastructure failure.
- Order: S01 + S02 gates -> 4a -> 4b -> 4c -> 4d -> combined winners (C1) x3 seeds.
- Rough budget: ~24 + 12 + 24 + 30 cell-runs at the declared token budget; S01 reports tokens/s, from which S03
  publishes the expected wall-clock.

## S03 queue declaration

S03 generated the runnable queue in `experiments/glm53_arch_speedrun/queue/cells.jsonl` and the design note in
`experiments/glm53_arch_speedrun/queue/DESIGN.md`. The generator is
`experiments/glm53_arch_speedrun/queue/generate_cells.py`; it was run inside the `glm53_train` rootfs and produced 93
runnable cells:

- 4a: 30 runs, with B0 x3 seeds and every add-one arm x2 seeds at seq 4096, plus the required seq-1024 replicate.
- 4b: 15 runs, with G x3 seeds and each leave-one-out arm x2 seeds at seq 4096.
- 4c: 48 runs, a 24-row fraction x2 seeds at seq 4096.

The 4c fraction is a deterministic mixed-level nonregular design over F1-F5. It enumerates the full `2^4 x 3`
candidate set, samples exactly eight rows from each sparse-attention level with seed `5303`, requires 12/12 balance on
each two-level factor, and accepts the first candidate whose registered model matrix has full rank for intercept, all
main effects, all binary-binary two-way interactions, and all binary-by-sparse two-way interactions. The accepted model
rank is `21/21`, so the preregistered main and two-way terms have no exact aliases. Higher-order effects are pooled
into residual error. The machine-readable alias declaration is
`experiments/glm53_arch_speedrun/queue/alias_structure.json`.

Effect coding for 4c: mHC off/on = -1/+1; positions RoPE/NoPE = -1/+1; mixer softmax/KDA 3:1 = -1/+1; MTP off/on =
-1/+1; sparse dense/indexer/indexer+IndexPool = `(1,0)`, `(-1,1)`, `(0,-1)`.

4d and C1 are intentionally deferred. S03 emitted templates in
`experiments/glm53_arch_speedrun/queue/deferred_4d_templates.jsonl` and
`experiments/glm53_arch_speedrun/queue/deferred_c1_templates.jsonl`, but they are not runnable until the preregistered
freeze rules have evidence: 4d chooses each element's better add-one versus leave-one-out context after 4a/4b; C1
includes every element whose mean validation CE improves by more than `2 * std(B0 seed CE)` after 4a-4d.

The host scheduler is `experiments/glm53_arch_speedrun/scheduler.sh`. It is host orchestration only: it reads GPU free
memory from `nvidia-smi`, launches at most six cells and at most two per GPU through the S01 runner, records per-cell
state under `experiments/glm53_arch_speedrun/queue/state/`, retries once only for infrastructure failures, calls the
rootfs analysis helper after each completed slice, and publishes per-run bundles via the Waystone publisher with MD5.
At S03 handoff, the S01 report was still missing and S02 reported its overfit/throughput gate as blocked on S01 arm
integration (`S01 runner supports B0 only; got A1`), so no matrix cell was launched.
