## Goal and Done Definition

The campaign goal is to hill-climb one SFT pipeline up this ladder:
Qwen3 0.6B/1.7B -> Qwen3 8B -> Qwen3 30B-A3B MoE -> mini KDA+sparse-attn
hybrid -> GLM-5.3-Flash LoRA, first on 4x and then on 8x B200
(`.scratch/glm53-flash-sft-ladder/spec.md`).

The done definition is GLM-5.3-Flash LoRA SFT on 8x B200 that loads the official
checkpoint from HDFS, passes pre-training logits parity against the HF reference,
improves held-out Countdown pass@1 over base across at least two seeds, resumes
from HDFS after a local cache wipe, runs at least 10 steady steps with throughput
and memory recorded, and publishes adapter, eval, and run bundle to HDFS with
MD5 verification (`.scratch/glm53-flash-sft-ladder/spec.md`).

The fixed task is Countdown SFT over `countdown-sft/v1`: the replicated champion
`formatting` arm plus dev/iid/ood splits from the prior Countdown search
distillation run. The pipeline uses `ChatProcessor` assistant-only loss masking,
the Countdown verifier/eval stack, and fixed tokens per optimizer step when GPU
count changes (`.scratch/glm53-flash-sft-ladder/spec.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-02-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07c-report.md`).

## Storage Contract

HDFS through Waystone is the system of record. Paths are resolved through
`waystone layout-profile --project torchtitan --json` and
`waystone storage-prefix --child`; the campaign does not hand-join HDFS paths
(`.scratch/glm53-flash-sft-ladder/spec.md`,
`experiments/glm53_flash_sft_ladder/README.md`,
`experiments/glm53_flash_sft_ladder/lib/waystone.sh`).

The campaign layouts are:

- `model-weights/<org>/<model>/<hf-revision>/`
- `datasets/<name>/<version>/`
- `checkpoints/glm53-ladder/<run_id>/<attempt_id>/`
- `runs/glm53-ladder/<run_id>/<attempt_id>/`

Local disk is a disposable cache rooted at `/data05/philip.yang/glm53-ladder-cache`.
The spec opened with `/data05` as the only spacious local disk, and T03 kept a
local staged copy with `hf_ingest.sh --keep-local` so one HF download fed both
HDFS and local training cache (`.scratch/glm53-flash-sft-ladder/spec.md`,
`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`experiments/glm53_flash_sft_ladder/ingest_ladder_models.sh`).

Authentication is external to the runners. The documented keepalive is
`~/.local/bin/waystone-auth-keepalive.sh`, which does `kinit -R` plus
`waystone auth keepalive` from cron. Runners intentionally avoid
`--refresh-token` because it may prompt non-interactively. If HDFS calls hang,
the environment note says the doas token is stale and to run the keepalive once
(`.scratch/glm53-flash-sft-ladder/spec.md`,
`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`experiments/glm53_flash_sft_ladder/README.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-01-brief.md`).

All published trees use `MANIFEST.jsonl` and `_COMPLETE`. `stage.sh` refuses
incomplete trees and verifies local files against manifest MD5s before writing
`.staged.json`; `publish.sh` uploads recursively with MD5 verification
(`experiments/glm53_flash_sft_ladder/README.md`,
`experiments/glm53_flash_sft_ladder/stage.sh`,
`experiments/glm53_flash_sft_ladder/publish.sh`).

## Environment

Host orchestration is allowed for Waystone, shell staging, result-directory
creation, `git status`, and log inspection. Python/model/CUDA/training/eval work
runs inside `scripts/rootfs/enter_rootfs.sh`
(`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`.scratch/glm53-flash-sft-ladder/spec.md`).

The rootfs has three relevant modes:

| Mode | Use | Command shape / notes | Sources |
| --- | --- | --- | --- |
| Default rootfs | vLLM eval and most non-Trainer export paths | No `TORCHTITAN_ROOTFS_ENV`; used for vLLM 0.27 eval because it is built for torch 2.13. | `.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`, `.scratch/glm53-flash-sft-ladder/sdd/task-02-report.md` |
| `glm53_train` | TorchTitan Trainer/FSDP/model tests | `TORCHTITAN_ROOTFS_ENV=glm53_train scripts/rootfs/enter_rootfs.sh -- bash -lc 'unset CC CXX; cd /workspace/torchtitan && ...'`; contains `torch==2.16.0.dev20261013+cu132`. | `.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`, `.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`, `.scratch/glm53-flash-sft-ladder/sdd/task-08b-report.md` |
| `glm53_ref` | HF Transformers oracle and bf16/fp32 diagnostics | `TORCHTITAN_ROOTFS_ENV=glm53_ref` with `TORCHTITAN_ROOTFS_FORMAL_CACHE_HOST=/data05/philip.yang/glm53-ladder-cache`; observed `transformers 5.19.0.dev0`, `torch 2.13.0+cu132`. | `.scratch/glm53-flash-sft-ladder/sdd/task-07c-report.md`, `.scratch/glm53-flash-sft-ladder/sdd/task-08c-report.md` |

`unset CC CXX` is mandatory inside rootfs commands because host `CC`/`CXX`
point at a Spack GCC path that does not exist inside the rootfs, and Triton
compilation fails otherwise (`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`).

The rootfs is offline by default. Networked install/download work uses
`TORCHTITAN_ROOTFS_NETWORK=networked scripts/rootfs/enter_rootfs.sh -- ...`, and
`uv` installs must constrain torch so the training stack is not replaced
(`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08c-report.md`).

The host RAM guard is `experiments/glm53_flash_sft_ladder/host_ram_guard.sh`.
It samples available host RAM and process RSS every 30 seconds by default,
filters its own PID out of the guarded PID set, sends TERM then KILL if the
floor is crossed, and was used around full GLM probes. T08b's launch rule kept
rank RSS under `120 GB`, while the global guard killed GLM ranks if available
RAM fell below `600 GB` (`experiments/glm53_flash_sft_ladder/host_ram_guard.sh`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08b-brief.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08b-report.md`).

## GLM Integration Seam

The GLM implementation is repo-local experiment code under
`torchtitan/experiments/glm53_flash/`, not core model code
(`.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`,
`git log --name-only --pretty=format:'...' 96760e290^..HEAD`).

`flavors.py` defines released, mini, debug, and LoRA-flavored GLM configs. The
released flavor has 45 layers, the 3:1 KDA:sparse schedule, 4-stream mHC,
288 routed experts top-8 plus one shared expert, first 3 dense layers, and the
vocab/norm/epsilon/head dimensions from the architecture contract
(`torchtitan/experiments/glm53_flash/flavors.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`,
`docs/research/2026-10-14-glm-5.3-flash-architecture-and-finetuning.md`).

`model.py` owns the text-only GLM model with mHC, KDA, sparse MLA plus
IndexPool/indexer, local MoE, dense-causal ablation, experiment-local LoRA
wrappers, and FSDP/activation-checkpoint lifecycle for a plain `nn.Module`
model tree (`torchtitan/experiments/glm53_flash/model.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07b-report.md`).

`state_dict_adapter.py` maps BF16 HF text decoder keys under
`model.language_model.*`, groups per-expert gate/up/down HF weights into native
expert tensors, reshapes `dt_bias`, expands grouped experts back to HF, and
explicitly skips `weight_scale_inv`, vision tower/projector keys, and MTP keys
(`torchtitan/experiments/glm53_flash/state_dict_adapter.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07c-report.md`).

`sharding.py` validates the current parallelism contract: tensor parallelism,
context parallelism, and pipeline parallelism are rejected. Expert parallel
degree is validated for divisibility, but token-dispatch expert-parallel
execution is not implemented in this GLM seam
(`torchtitan/experiments/glm53_flash/sharding.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07a-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-11-brief.md`).

LoRA trainability is strict. `apply_lora_trainable_policy` leaves only parameter
names ending in `.lora_a` or `.lora_b` trainable, and the full GLM optimizer
pattern is `.*\.lora_[ab]$`. T08 tests assert the full rank-16 LoRA trainable
parameter count is exactly `67,190,784`
(`torchtitan/experiments/glm53_flash/model.py`,
`torchtitan/experiments/glm53_flash/config_registry.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08b-report.md`).

The rank-local loader in `sharded_hf_load.py` is the main T08b unblock. It
iterates live parameters/buffers after FSDP, computes DTensor local shapes and
global offsets, reads only needed safetensor slices with
`safe_open(...).get_slice(...)`, handles flattened `dt_bias` and grouped expert
tensors, skips LoRA tensors, and verifies selected slices against direct HF
safetensor reads (`torchtitan/experiments/glm53_flash/sharded_hf_load.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08b-report.md`).

`Glm53FlashLoRACheckpointManager` reloads the frozen HF base through the
rank-local loader and wraps model state with `TrainableModelWrapper`, so
checkpoint model state exposes only trainable tensors while optimizer,
scheduler, dataloader, RNG, and train-step state remain regular checkpoint
manager responsibilities (`torchtitan/experiments/glm53_flash/checkpoint.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08b-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08d-brief.md`).

The Countdown data path uses GLM's real tokenizer/chat template with
assistant-only labels. T07c evidence shows prompts begin with
`[gMASK]<sop><|system|>Reasoning Effort: Max...`, prompt-only rendering ends
with `<|assistant|><think>`, full training rendering inserts an empty thinking
block before the answer, and prompt/system/user tokens are set to `IGNORE_INDEX`
(`torchtitan/experiments/glm53_flash/config_registry.py`,
`torchtitan/experiments/glm53_flash/hf_parity.py`,
`.scratch/glm53-flash-sft-ladder/sdd/task-07c-report.md`).

## Numerics

The DeepSeek-V4 `HcPost` axis bug was confirmed before the GLM seam landed and
fixed in `96760e290`. The bug was that TorchTitan had flattened batch/sequence
to `[T, hc, D]` but kept the reference expression that sums `dim=2`; in the
flattened layout that sums the target stream axis instead of the source stream
axis. The correct formula is equivalent to `comb.transpose(-1, -2) @ residual`
(`.scratch/glm53-flash-sft-ladder/sdd/task-04-report.md`,
`tests/unit_tests/test_deepseek_v4_mhc_post.py`,
`torchtitan/models/deepseek_v4/mhc.py`,
`git log --oneline 96760e290^..HEAD`).

T07c is the fp32 GLM real-weight identity gate. It used real embeddings, selected
real transformer layers, final norm, `lm_head`, four Countdown prompts rendered
with the GLM chat template, and one 4096-token synthetic sequence. Fp32 slices
0-3 and 20-27 both had min top-1 `1.0`; sparse selection masks matched exactly
for fp32. The middle-slice outlier is recorded, not hidden: sample
`cd-17-95-3-t75`, layer 26 `linear_attention`, max abs
`0.045856863260269165`, final logits max abs `0.7716797590255737`, with top-1
still `1.0` and KL `0.00019110699940938503`
(`.scratch/glm53-flash-sft-ladder/sdd/task-07c-report.md`).

T08c diagnosed the bf16 gap against HF-fp32 truth. TT-bf16 was not the outlier:
TT-bf16 and HF-bf16 were essentially equally far from fp32 truth on layers
20-27. The accepted summary table reported TT-bf16 min top-1
`0.02631578966975212`, max KL `1.3880523443222046`, max final abs
`27.459651947021484`, max layer abs `44.55101776123047`; HF-bf16 min top-1
`0.02631578966975212`, max KL `1.3974062204360962`, max final abs
`27.584596633911133`, max layer abs `45.30101776123047`
(`.scratch/glm53-flash-sft-ladder/sdd/task-08c-report.md`,
`torchtitan/experiments/glm53_flash_bf16_diag/bf16_truth_diag.py`).

## Incidents and Lessons

T08 host-RAM incident: mode B used CPU offload plus the active DCP/HF initial
load path. That path materialized full model-shaped state per rank and was
killed before step 1 at about `263 GiB` RSS/rank; map.md records the incident
as roughly `248-263 GiB` RSS/rank. The guard response is to use mode A,
rank-local safetensor loading, trainable-only checkpoint state, and
`host_ram_guard.sh` with per-rank RSS sampling
(`.scratch/glm53-flash-sft-ladder/map.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08b-report.md`,
`experiments/glm53_flash_sft_ladder/host_ram_guard.sh`).

Stale doas token hangs: the environment note says Waystone auth is maintained by
cron and that a hang means the doas token is stale; the operator should run
`~/.local/bin/waystone-auth-keepalive.sh` once
(`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`experiments/glm53_flash_sft_ladder/README.md`).

Rootfs dependency drift: T00 fixed out-of-sync rootfs deps and established that
Trainer/FSDP requires the `glm53_train` torch nightly environment, while vLLM
eval remains on the default rootfs environment
(`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`.scratch/glm53-flash-sft-ladder/sdd/progress.md`).

Pyrefly hook auto-edits: the campaign notes say to run only relevant hooks on
changed files because `pyrefly` currently fails repo-wide and may auto-edit
unrelated core files. Reports consistently skipped full repo pre-commit for
that reason (`.scratch/glm53-flash-sft-ladder/sdd/env-facts.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-02-report.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-08c-report.md`).

Worker reverting a fix: T10 lists this as a campaign lesson, and the handoff
logs explicitly call the committed `HcPost` fix protected work that must not be
reverted. Treat committed numerical fixes inside the campaign window as
protected unless an explicit follow-up ticket says otherwise
(`.scratch/glm53-flash-sft-ladder/sdd/task-10-brief.md`,
`experiments/glm53_flash_sft_ladder/logs/t01.last.md`,
`experiments/glm53_flash_sft_ladder/logs/t07a.last.md`,

`pkill` self-match: T10 lists self-match as a lesson, and the current
`host_ram_guard.sh` implements PID filtering with `awk -v self="$$"` before it
kills guarded PIDs. Keep that pattern for future process guards
(`.scratch/glm53-flash-sft-ladder/sdd/task-10-brief.md`,
`experiments/glm53_flash_sft_ladder/host_ram_guard.sh`).

Triton autotune OOM plus prewarm: the first T08b full probe loaded rank-local HF
shards successfully but later failed in KDA l2norm backward autotuning with a
Triton CUDA OOM. A corrected prewarm call for `_l2norm_fwd_cuda(x, 1.0e-6, None)`

`.scratch/glm53-flash-sft-ladder/sdd/task-08d-brief.md`,
`.scratch/glm53-flash-sft-ladder/sdd/task-09-common.md`).
