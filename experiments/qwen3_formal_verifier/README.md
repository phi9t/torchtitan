# Qwen3 Accelerator Observability

This experiment provides a backend-neutral observability substrate for
TorchTitan accelerator work, plus a Qwen3 DPxTP formal verifier built on top of
that substrate. It stays under `experiments/` so real training code can consume
or replace pieces incrementally without making formal tooling part of the core
runtime path.

The package has three layers:

- `schema.py`, `verifier.py`, `emulator.py`, and `model_export.py` define the
  generic accelerator trace IR, lifecycle verifier, deterministic logical
  emulator, and backend-erased model export helpers;
- `tracer.py` defines a Torch semantic tracer API for module path, ATen
  dispatcher correlation, tensor placement, autograd readiness, process group,
  executor, collective, and P2P events;
- `qwen3_step.py` builds one TorchTitan-style dense Qwen3 training step and
  exports the corresponding TLA+ and Lean facts.

The Qwen3 model focuses on the DPxTP mesh facts that performance tracing and
formal reasoning need to agree on:

- rank-to-DP/TP coordinates and process-group membership;
- Torch module, ATen dispatcher, tensor-placement, and autograd readiness
  events;
- collective work identity, enqueue/start/complete lifecycle, stream executor
  assignment, and producer correlation;
- TLA+ and Lean facts generated from the same Python trace IR.

The runtime code lives in `torchtitan.experiments.qwen3_formal_verifier`. The
checked-in formal files under `formal/` are generated by
`write_qwen3_step_formal_artifacts` and are kept in sync by
`tests/unit_tests/test_qwen3_formal_verifier.py`. The generic accelerator and
semantic tracer contracts are covered by
`tests/unit_tests/test_generic_accelerator_observability.py`.
